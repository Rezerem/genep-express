# Static Piste Data

This directory contains static ski piste data for the application.

## Setup

Before running the application for the first time (or to refresh the data):

```bash
npm run download-pistes
```

This will:
1. Query Overpass API for ski pistes in the 3 Vallées region (Val Thorens, Méribel, Courchevel)
2. Transform the data to GeoJSON format
3. Save as `pistes-static.geojson`

## Files

- `pistes-static.geojson` — Static ski piste data for 3 Vallées region (generated by download script)

## Data Source

- **Source**: Overpass API + OpenStreetMap
- **Region**: 3 Vallées (French Alps)
- **Coverage**: Val Thorens, Méribel, Courchevel
- **Update frequency**: Manual (run script as needed)
- **Format**: GeoJSON FeatureCollection

## Piste Attributes

Each feature includes:
- `name` — Piste name
- `difficulty` — blue, red, black, green, etc.
- `type` — downhill, nordic, skitour
- `grooming` — grooming status
- `status` — open, closed, etc.
- `lit` — whether the piste is lit (night skiing)

## Why Static Data?

Ski pistes don't change frequently, making static data appropriate for this use case. This approach:
- ✅ Eliminates external API dependency
- ✅ Improves performance (no runtime queries)
- ✅ Reduces latency for mobile clients
- ✅ Simplifies deployment

## Refreshing Data

To update the piste data before a deployment:

```bash
npm run download-pistes
# Commit the updated pistes-static.geojson
git add src/data/pistes-static.geojson
git commit -m "chore: refresh piste data"
```

## Troubleshooting

### Script fails with "Overpass API error"
- Check Overpass API status: https://overpass-api.de/status.html
- Wait for maintenance to complete
- Retry the script

### Script fails on Windows
- Use WSL2 or Git Bash
- Alternatively, run from the root directory using bash explicitly:
  ```bash
  bash api/scripts/download-pistes.sh
  ```

### Script takes too long
- Overpass API is rate-limited and can be slow during peak hours
- Typical runtime: 30-60 seconds
- You can interrupt (Ctrl+C) and retry later

## File Size

Expected size: ~100-200 KB depending on data completeness
